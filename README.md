# Система управления и учета мультимедийного оборудования

Веб-приложение для учета мультимедийного оборудования и управления его использованием при организации мероприятий.

Проект разработан в рамках выпускной квалификационной работы на тему:

> **«Разработка базы данных для управления и учета мультимедийного оборудования»**

## 📋 Возможности

Система позволяет:

* просматривать список мультимедийного оборудования;
* добавлять новое оборудование;
* удалять оборудование;
* отслеживать текущее состояние оборудования;
* создавать и редактировать мероприятия;
* назначать оборудование на мероприятия;
* автоматически изменять статус оборудования при его использовании;
* автоматически освобождать оборудование после завершения мероприятия;
* просматривать список пользователей;
* разграничивать права доступа по ролям;
* выполнять авторизацию пользователей;
* использовать JWT для управления сессией;
* вести журнал действий пользователей;
* работать с базой данных PostgreSQL через REST API.

### Типы оборудования

В системе могут учитываться различные категории мультимедийного оборудования, например:

* усилители;
* пульты управления;
* ноутбуки;
* акустические системы;
* активные и пассивные колонки;
* сабвуферы;
* сценические мониторы;
* микрофоны;
* радиосистемы;
* другое оборудование.

# 🗄 База данных

Проект использует PostgreSQL.

Основные сущности базы данных:

```text
users
role
equipment
status
location
event
event_equipment
```

### Связи

Пользователь связан с ролью:

```text
role 1 ──────── N users
```

Мероприятие может использовать несколько единиц оборудования, а одна единица оборудования может участвовать в разных мероприятиях в разное время:

```text
event 1 ──────── N event_equipment N ──────── 1 equipment
```

Оборудование также связано со своим состоянием и местоположением.

---

# 🔐 Авторизация

Для авторизации используется JWT.

После успешного входа сервер:

1. проверяет email и пароль;
2. сравнивает пароль с bcrypt-хэшем;
3. создаёт JWT;
4. сохраняет JWT в `httpOnly` cookie;
5. возвращает данные авторизованного пользователя.

Cookie имеет следующие параметры:

```text
httpOnly: true
sameSite: lax
maxAge: 8 часов
```

Пароли пользователей хранятся в базе данных в виде bcrypt-хэшей.

---

# 👥 Роли пользователей

Система предусматривает разграничение доступа пользователей.

Роль пользователя определяется через таблицу `role`.

Пример:

```text
users
   │
   └── role_id → role.role_id
```

Роль пользователя также передаётся в JWT и используется сервером для проверки доступа к защищённым операциям.

---

# 📦 Управление оборудованием

Для каждой единицы оборудования хранится информация, необходимая для его учета.

Оборудование может иметь различные состояния, например:

```text
Свободно
Занято
В ремонте
Неисправно
```

При назначении оборудования на мероприятие его статус изменяется на:

```text
Занято
```

После завершения мероприятия оборудование снова становится доступным:

```text
Свободно
```

---

# 🎤 Мероприятия

Система позволяет создавать мероприятия и назначать на них доступное оборудование.

При создании мероприятия:

1. пользователь указывает основные данные мероприятия;
2. система показывает доступное оборудование;
3. выбранное оборудование связывается с мероприятием;
4. его статус изменяется на `Занято`.

Для связи используется таблица:

```text
event_equipment
```

После окончания мероприятия оборудование освобождается.

Статусы мероприятия:

```text
Предстоящее
Завершено
```

# 🐘 Настройка PostgreSQL

1. Запустить службу PostgreSQL.
2. Открыть pgAdmin.
3. Создать базу данных.
4. Выполнить SQL-скрипт создания таблиц проекта.
5. Заполнить таблицы начальными данными.

Проверить, что PostgreSQL работает на порту:

```text
5432
```

Проверка в Windows:

```bash
netstat -ano | findstr 5432
```

Если PostgreSQL не запущен, приложение не сможет подключиться к базе данных.

# 🔒 Безопасность

В проекте реализованы следующие механизмы:

* хэширование паролей с помощью bcrypt;
* JWT-аутентификация;
* хранение JWT в `httpOnly` cookie;
* проверка авторизации на защищённых маршрутах;
* разграничение доступа по ролям;
* использование параметризованных SQL-запросов;
* хранение конфиденциальных настроек подключения в `.env`.

Пароли пользователей не должны храниться в базе данных в открытом виде.

# 🐛 Возможные проблемы

## PostgreSQL не подключается

Ошибка:

```text
connection timeout expired
```

Проверить:

1. Запущена ли служба PostgreSQL;
2. работает ли сервер на `localhost`;
3. используется ли правильный порт;
4. совпадают ли данные подключения в `.env`;
5. существует ли указанная база данных.

Проверка порта:

```bash
netstat -ano | findstr 5432
```

---

## Ошибка авторизации

Проверить:

* правильность email;
* пароль;
* наличие пользователя в таблице `users`;
* наличие bcrypt-хэша в `password_hash`;
* значение `JWT_SECRET`;
* подключение backend к PostgreSQL.
